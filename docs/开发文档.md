# DevQuest 完整开发文档

> DSH（DeepSeek Harness）开发游戏化成就插件。本文档覆盖：技术调研结论、架构设计、数据模型、数值设计、成就清单、客户端 UI、开发里程碑、GitHub 发布流程。开发前请通读。

- 项目名：`dsh-devquest`（npm 包名候选：`dsh-devquest`）
- 目标平台：DSH Web（client platform: web）+ host 工具（headless 亦可用）
- 文档版本：v1.0
- 状态：待开发（M1 未开工）

---

## 1. 项目定位

把「和 agent 一起写代码」变成 RPG。agent 的每次行动（turn 完成、工具调用、todo 完成、token 产出、深夜活跃）都在给用户积累 XP，解锁成就徽章，有等级曲线和赛季。

**与生态差异**：DSH 社区现有游戏类插件全是「给用户摸鱼的小游戏」（五子棋、自走棋、18 款离线小游戏、桌宠）。DevQuest 是第一个把**开发活动本身**游戏化的插件——工作即游戏，天然有传播点。

**受众**：所有重度使用 DSH 的开发者。对游戏行业开发者尤其有共鸣（数值、成就、赛季设计可玩梗）。

## 2. 技术调研结论（已验证，开发直接照此实现）

以下 API 均已在**本机 DSH 安装**中逐一读取验证，非推测。

### 2.1 事件源：`ctx.sessions` + `session/event`

来源：`@deepseek-ai/dsh-session`（lib/types/index.d.ts + types.d.ts）

```ts
declare module '@deepseek-ai/cordis' {
    interface Context { sessions: SessionStore; }
    interface Events {
        'session/created'(session: Session): void;
        'session/disposed'(session: Session): void;
        'session/event'(session: Session, event: SessionEvent): void;   // ★ 核心
        'session/flush'(session: Session): Promise<void> | void;
    }
}
```

**`session/event` 是 fire-and-forget 的 append feed**：post-commit 触发，回调在日志推送后执行；监听器失败仅记录不影响提交。订阅方式：

```ts
ctx.on('session/event', (session, event) => {
    // event.type 判别 + event.data 载荷
});
```

**可用事件类型**（`SessionEventMap`，即成就触发的全部信号）：

| 事件类型 | 载荷要点 | 对 DevQuest 的意义 |
|---|---|---|
| `turn/start` | `{turn}` | 回合开始 |
| `turn/end` | `{turn, reason}` | ★ reason: `completed` \| `aborted` \| `blocked` \| `error` \| `max-tokens`（`TurnEndReasonMap`，merge-extensible） |
| `step/start` / `step/end` | `{turn, step}` | 模型调用步 |
| `user/message` | `UserMessage`（含 `source`：真人 prompt / agent.inject / goal 轮） | 区分真人交互与系统注入 |
| `assistant/message` | `{turn, step, message, usage?}` | ★ `usage: TokenUsage`（token 用量） |
| `tool/call` | `{turn, step, callId, name, arguments}` | ★ 工具调用（`name` 为工具名） |
| `tool/result` | `{turn, step, message, error?, meta?}` | ★ `error: {name, code}`（工具失败）；`meta` 工具私有载荷 |
| `todo/write` | `{todos: TodoItem[]}`（whole-list 快照，`TodoItem.status`: pending/in_progress/completed） | ★ 任务闭环判定 |
| `request/header` | `{header: EpochHeader, reason}` | 模型/工具配置快照 |
| `request/context` | `RequestContext`（`provider`, `model`, `contextWindow?`） | ★ 模型路由（provider/model） |
| `session/end-seed` | `{}` | 种子边界（resume/fork） |

**`Session` 对象**（`session/event` 第一个参数）提供：

```ts
session.header: SessionHeader   // {id, createdAt, cwd?, parentSession?, delegationDepth?, agentPreset?}
session.id: SessionId
session.seq: number             // 事件序号（单调）
session.events: readonly SessionEvent[]  // 不可变快照
```

`SessionHeader.delegationDepth`（子代理深度）与 `cwd` 可用于「子代理委派」「项目隔离」成就。

**事件对象结构**（判别联合）：

```ts
type SessionEvent = {
    type: K;          // 判别字段
    seq: number;      // 会话内单调序号
    time: number;     // Unix epoch ms
    data: SessionEventMap[K];
    ignorable?: true; // 未知类型可安全跳过
} & (K extends SurfaceEventType ? { sourceEventSeqs?, surfaceOp? } : object)
```

ctx.tools.register(defineTool({

        return await engine.status(args.detail === 'full');

## 3. 架构设计

```
host 侧 (src/index.ts)
├── src/listener.ts     订阅 session/event → 归一化为 Action 流
├── src/engine.ts       纯函数计分：Action → (xp, unlockedAchievements[])   ← 可单测核心
├── src/store.ts        存档读写（ctx.fs）：load/save/migrate
├── src/tools.ts        devquest 工具（status / achievements / reset）
├── src/routes.ts       GET /api/devquest/status（面板数据源，60s 缓存）
└── src/types.ts        Action / SaveData / AchievementDef 类型

client 侧 (src/client/)
├── index.ts            slots 注册 + locale 注册
├── DevQuestPanel.tsx   侧边栏面板：等级环 + XP 进度条 + 最近成就 + 成就墙
├── store.ts            面板状态（fetch /api/devquest/status，轮询）
└── locales.ts          zh/en 字典

根目录
├── package.json        manifest（dsh.bundle / dsh.client）
├── cordis.patch.yml    挂载条目
├── tsconfig.json / tsdown.config.ts / build 脚本（参考 context-doctor）
└── tests/              engine 单测（node --test，零依赖）
```

**数据流**：

```
session/event ──► listener 归一化 ──► engine.score(action, save) ──► 新 save
                     │                                              │
                     └── Action{turn, tool?, reason?, source?,      └──► store.save(ctx.fs)
                               todoCompleted?, tokens?, provider?}
                                                                    │
devquest_status 工具 ◄── engine.status(save) ◄── store.load ◄───────┘
        ▲
        └── client 面板 ◄── HTTP /api/devquest/status
```

**关键不变式**：
1. **engine 是纯函数**：`score(save, action) → save'` 无 I/O 无副作用 → 全部可单测
2. **幂等**：listener 按 `session.id + event.seq` 去重（内存 Set + 存档 lastSeq），重启重放不重复计分
3. **事件处理不抛**：listener 包 try/catch，任何异常只记录不影响 session 提交

### 4.2 归一化 Action

```ts
type Action =
  | { kind: 'turn-completed'; turn: number }
  | { kind: 'turn-failed'; turn: number }
  | { kind: 'turn-aborted'; turn: number }
  | { kind: 'tool-call'; tool: string }
  | { kind: 'tool-failed'; tool: string }
  | { kind: 'todo-completed'; count: number }
  | { kind: 'tokens'; tokens: number }
  | { kind: 'subagent'; depth: number }
  | { kind: 'session-start'; hourOfDay: number; source: string }
```

### 4.3 成就定义

```ts
interface AchievementDef {
    id: string;                 // kebab-case 唯一
    name: { zh: string; en: string };
    description: { zh: string; en: string };
    icon: string;               // emoji 或路径
    xp: number;                 // 解锁奖励 XP
    hidden?: boolean;           // 彩蛋（解锁前不显示）
    /** 判定：基于 counters 的纯函数 */
    check: (c: Counters) => boolean;
}
```

## 5. 数值设计（v1 初稿，开发时按手感调）

### 5.1 XP 映射

| 事件 | XP | 规则 |
|---|---|---|
| `turn/end` completed | +10 | |
| `turn/end` error | +2 | 参与分 |
| `turn/end` aborted/max-tokens | +0 | 不奖励不惩罚 |
| `tool/call` 任意 | +1 | 单 turn 封顶 +10（listener 按 turn 聚合） |
| `tool/call` edit/write/pwsh/ssh/str-replace | +2 | 「锻造师」工具加成（不叠加 +1） |
| `tool/result` error | +0 | 只触发成就判定 |
| `todo/write` 新增 completed | +15 | 按新增完成数 |
| `assistant/message` usage | 每 10k tokens +1 | 向下取整 |
| 连击（连续 completed） | ×1.5 加成 | 连击 ≥5 起，加到本轮 XP |

### 5.2 等级曲线

```
xpToNext(level) = round(100 × level^1.5)
L1→2: 100    L2→3: 283    L3→4: 520    L4→5: 800    L5→6: 1115
L6→7: 1461   L7→8: 1832   L8→9: 2225  L9→10: 2640  L10→11: 3074
```

称号（每 5 级一档）：

| 等级 | 称号 |
|---|---|
| 1-4 | 学徒 Apprentice |
| 5-9 | 工匠 Artisan |
| 10-14 | 锻造师 Forger |
| 15-19 | 宗师 Master |
| 20+ | 传说 Legend |

### 5.3 防刷规则

1. 成就一次性（存档 `achievements` 记录 acquiredAt，不可重复解锁）
2. 工具 XP 单 turn 封顶 +10（listener 维护 turn 级聚合缓冲，turn/end 时结算）
3. 存档按 cwd 作用域（不同项目独立进度）；`~/.dsh/devquest/` 全局元数据（activeDays 等跨项目）单独文件
4. 幂等：按 `session.id + event.seq` 水位去重，重放不重复计分
5. `devquest reset` 工具：清空指定 cwd 存档（谨慎，需确认参数）

## 8. 开发里程碑

### M1 — 最小闭环（可跑通验证事件源）

**目标**：监听事件 → 计分 → 存档 → `devquest_status` 工具返回等级/XP。

文件：
- `src/types.ts`（Action/SaveData/Counters 类型）
- `src/listener.ts`（订阅 session/event，归一化 Action，幂等水位）
- `src/engine.ts`（score 纯函数 + xpToNext + 等级晋升）
- `src/store.ts`（ctx.fs 读写）
- `src/tools.ts`（devquest_status 工具）
- `src/index.ts`（apply 装配：inject ['fs','sessions','tools']）
- `package.json` / `cordis.patch.yml`（先 host-only，无 client）

**验收**：
1. `dsh plugin --profile web add <本地路径>` 装进本机 profile
2. 真实会话跑 3 轮（含 1 次工具调用），`devquest_status` 返回 XP 递增
3. 重启 web 后重放历史事件不重复计分（幂等）

**目标**：24 枚成就判定 + 一次性 + 彩蛋 + 连击。

## 9. 本地开发与测试指南

### 9.1 依赖

- Node ≥ 22.19（build/test 用；构建产物入库后用户无需）
- 本机 DSH checkout（`scripts/setup-dsh-deps.mjs` 参考 context-doctor 链接 `@deepseek-ai/*` 包）

### 9.2 开发循环

```sh
# 1. 首次：链接 DSH 依赖
node scripts/setup-dsh-deps.mjs

# 2. 单测（纯函数引擎，零依赖）
node --test 'tests/*.test.ts'

# 3. 构建（tsc + tsdown → lib/）
./scripts/build.sh

# 4. 装进本机 profile（link 模式）
dsh plugin --profile web add <repo 本地路径>
#    构建产物必须入库（lib/ 提交），否则用户 git 源安装后无产物可用

# 5. 验证合成树
dsh --profile web --dump-config | grep devquest
```

### 9.3 常见坑（踩过）

| 坑 | 解法 |
|---|---|
| `git clone` / pnpm git 协议网络失败 | 本机走 codeload zip 下载源码到 `~/dsh-plugin-src/`，再 `dsh plugin add <路径>`（link 装） |
| link 安装的插件 remove 后 node_modules junction 残留 | `Remove-Item <profile>\node_modules\<name> -Force -Recurse` |
| 插件改动后不生效 | 改过源码必须重新 `./scripts/build.sh`（lib/ 入库）+ 重启 web |
| 客户端插槽不存在 | 先读 `dsh-client-ui-sidebar`/`dsh-client-ui-slots` 的 SlotMap 声明确认插槽名 |
| 事件重放重复计分 | 存档 `events.lastSeqBySession` 水位 + listener 内存 Set |

## 10. GitHub 发布流程

### 10.1 仓库初始化

```sh
# 在 GitHub 建空仓库 <your-org>/dsh-devquest（README 用本仓库的 README.md）
git init

```

> ⚠️ 本机 git 网络问题：`git push` 走 SSH 可能被墙，可改用 HTTPS + token，或先本地开发到 M4 再推。

### 10.2 仓库必备文件

| 文件 | 要求 |
|---|---|
| `README.md` | 玩法介绍 + 安装命令 + 截图（M4 补） |

| `package.json` | `dsh.bundle.patch` + `dsh.client` manifest；`files: ["lib", "cordis.patch.yml"]`；`"private": true` |
